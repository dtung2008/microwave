## 第一小時 — 原理 I：全景，以及 dB 這門語言（0:00–0:50）

### 1.1 這門課為什麼存在（0:00–0:10）

投影片提示：六格圖 — 基地台、77 GHz 車用雷達晶片、機場監視雷達天線罩、四旋翼
無人機（drone/UAV）、衛星天線、拆開的 WiFi 路由器。

開場先講主張，不講定義。這六個系統其實是同一部機器：發射端把微波能量推進空間，
空間做它一貫做的事 — 擴散、反射、衰減 — 接收端再從熱雜訊裡把倖存的訊號挖出來。
WiFi 鏈路和戰鬥機的射控雷達差在**數字**，不差在物理。這門課教的就是這部機器：
導引能量的被動電路（第 2–9 講）、在雜訊中求生的接收機（第 10–12 講），以及把這一切
變成「偵測」的系統 — 偵測飛機、飛彈、無人機（第 13–16 講）。

今天的三個主張 — 寫在黑板上，留到下課：

1. **在微波頻率，導線本身就是元件。** 當實體尺寸與波長可比，克希荷夫定律
   （Kirchhoff's laws）不再是真理，第 2 講的傳輸線（transmission line）才是。
   今天你會親手算出那條界線在哪裡。
2. **dB 是母語，而且它有文法。** 鏈路預算（link budget）是一長串乘法；換成 dB
   就變成一串加法，凌晨兩點的工程師也能稽核 — 前提是每個數字都帶著單位。今天的
   結尾，就是一個沒帶單位的數字說出的 30 dB 謊言。
3. **雷達方程式（radar equation）就是 Friis 公式對摺一次。** 它的 R⁴ 是整門課
   最有分量的指數：它決定偵測一架無人機要花多少錢、匿蹤（stealth）買到什麼，
   以及為什麼監視雷達的天線像一棟房子。

先擋掉無線通訊背景同學心裡正在成形的問題：「鏈路預算我熟 — 這門課會不會都是
複習？」誠實回答：第一小時刻意從你的主場出發 — 從 Friis 開始，因為你已經擁有它；
再把它摺成雷達方程式，因為多數人還沒有。到第二小時，數字就全是雷達的數字；到第
4 講，課程會走進通訊課從來不進去的地方 — 你的鏈路預算裡永遠被抽象成一個 NF 數字
的那些匹配網路、耦合器、低雜訊前端，我們要一格一格打開。

### 1.2 頻譜地景 — 誰住在哪裡、為什麼（0:10–0:20）

投影片提示：300 MHz 到 300 GHz 的頻譜尺，標好住戶。

以偵測系統當主力住戶，沿著尺走一遍：

- **L 頻段（1–2 GHz）：** 遠程航路監視雷達（ARSR）；波長約 20 公分 — 天氣幾乎
  無感，天線巨大，解析度粗。
- **S 頻段（2–4 GHz）：** 機場監視、氣象雷達；WiFi 的 2.4 GHz 蹲在下緣 — 和你
  微波爐加熱剩菜是同一套物理。
- **X 頻段（8–12 GHz）：** 射控、船用雷達、**本課程的課程雷達** — 波長 3 公分，
  天線一人高，波束幾度寬。
- **K/Ka（18–40 GHz）：** 測速雷達、衛星上行。
- **W 頻段，77 GHz：** 車用避撞（collision avoidance）雷達 — λ ≈ 4 mm，天線
  陣列塞進一顆晶片，第 15 講就住在這裡。

沿尺而下的那條交換法則，說一次、用一學期：**頻率愈高，同樣孔徑買到愈小的硬體與
愈窄的波束；代價是大氣損耗、元件成本與功率。** 無人機偵測雷達選頻段，靠的正是
這條法則 — 先記著，它是第 15 講的作業。

接著是 λ 論證，數字上黑板。λ = c/f：50 Hz 時是 6000 公里 — 電力系統一輩子不用
想這件事；2.4 GHz 時 12.5 公分；10 GHz 時 3 公分；77 GHz 時 4 mm。一條 3 公分的
PCB 走線，在 1 MHz 是 10⁻⁴ 個波長 — 一條導線；在 2.4 GHz 是四分之一波長 — 一個
有自己主張的元件；在 10 GHz 是整整一個波長 — 不管你要不要，它就是天線。寫進
符號帳（notation ledger）的經驗法則：**超過約 λ/10，分布效應（distributed
effects）就開始作主。** 第 3 小時會把這張表印出來。

先擋掉必問題：「微波到底從哪裡開始？」誠實答案：那是文化，不是邊界 — 慣例說
300 MHz–300 GHz，但真正的判準是 λ/10 對上**你的**幾何尺寸。30 MHz 的 10 公尺
天線塔是在做微波工程；1 GHz 的 1 mm 電晶體（還）不是。

### 1.3 把分貝學好（0:20–0:32)

板書 — 這是全課程的算術，必須練成反射動作。

定義，講到精確為止，因為 bug 都從這裡孵出來：

> dB = 10·log₁₀（功率比）。永遠是功率。永遠是**比值**。
> dBm = 相對 1 mW 的 dB — 絕對功率穿著比值的衣服。
> dBi = 天線增益相對全向（isotropic）。dBsm = 雷達截面積（RCS）相對 1 m²。

現在就背起來的五個數字：×2 = +3.01 dB；×10 = +10 dB；×½ = −3.01 dB；
kT₀ = **−173.98 dBm/Hz** ≈ −174（290 K 參考溫度下的每赫茲熱雜訊底 — 地球上
每一張接收機規格表都對著它報數）；0 dBm = 1 mW。其餘全是加法：1 MHz 頻寬比
1 Hz 高 60 dB，所以雜訊底線（noise floor）是 −174 + 60 = −114 dBm。第 3 小時
會印出 −113.98。

文法，框在黑板上：

> dBm + dB = dBm（功率過增益 — 合法）
> dBm − dBm = dB（兩功率相比 — 合法，得到比值）
> **dBm + dBm = 胡說**（把兩個功率相乘 — 物理不做這種事）

戰場故事，60 秒：某衛星終端設計審查，一格試算表 `=P_tx + G_ant`，P_tx 一組人用
dBW 填、另一組人當 dBm 讀。三十 dB — 一千倍 — 明晃晃地藏著，不是審查抓到的，
是屋頂上鏈路死活不通才抓到的。本課程每個數字的單位都寫進**名字**裡：`p_t_dbm`、
`p_t_w`、`fspl_db`。作業工具箱全面強制這個慣例，第 3 小時會把這個 bug 重演一次。

### 1.4 Friis 傳輸公式 — 推導兩次（0:32–0:45）

單向問題：功率 P_t 經增益 G_t 的天線發射，距離 R 處增益 G_r 的天線收到多少？

**第一層 — 能量擴散（快版推導）。** 全向輻射把 P_t 攤在球面上：功率密度
S = P_t/4πR²。真實天線會集中：S = P_tG_t/4πR²。接收天線端出等效孔徑
（effective aperture）A_e，接住 P_r = S·A_e。天線理論（第 13 講證明）說
A_e = G_rλ²/4π。相乘：

> P_r = P_t G_t G_r λ² / (4πR)² — Friis 公式。

**第二層 — 用 dB，工程師的實際寫法。** 定義自由空間路徑損耗（free-space path
loss）FSPL = (4πR/λ)²，即 FSPL_dB = 20·log₁₀(4πRf/c)。於是：

> P_r[dBm] = P_t[dBm] + G_t[dBi] + G_r[dBi] − FSPL[dB]

錨定公式的那個數字：**FSPL(1 GHz, 1 km) = 92.45 dB。** 第 3 小時印它，作業檢查器
要它。

先擋掉 λ² 種下的誤解：「頻率愈高，空間吃掉愈多功率？」不 — 自由空間無損（第 3
小時用 scikit-rf **量**給你看，結果會讓人意外）。λ² 住在接收孔徑裡：增益固定的
天線隨頻率升高而實體縮小，接得就少。改成固定**天線尺寸**，G_r 隨 f² 長大，把
FSPL 的 λ² 對消，鏈路反而**變好**。λ² 究竟坐在哪裡 — 孔徑，不是介質 — 正是
這門課要練成本能的那種記帳。Friis 1946 年的原始論文 [R21] 只有兩頁，列為指定
閱讀，是一堂「話說得剛剛好」的大師課。

黑板算例（作業裡的 WiFi 鏈路）：2.4 GHz、P_t = 20 dBm、G_t = 6 dBi、G_r = 2 dBi、
B = 20 MHz、NF = 7 dB。在 50 公尺：FSPL = 74.03 dB，P_r = 20 + 6 + 2 − 74.03 =
**−46.03 dBm**。雜訊底：−174 + 73（20 MHz）+ 7 = −94 dBm。SNR = **47.93 dB** —
奢侈。在 1 公里：**21.91 dB** — 仍然從容。預算表的全部人格，就是每一行都是
帶名字、帶單位的項目。

### 1.5 本小時回顧（0:45–0:50）

三句話，然後休息：微波就是用波長丈量幾何的地方，而你現在會算那條界線；dB 是一套
文法，兩個合法動作、一個重罪；Friis 是擴散乘孔徑，(1 GHz, 1 km) 處 92.45 dB，
λ² 住在天線裡、不在空間裡。第二小時，把這套機器對準一個不想被看見的目標。

**休息（0:50–1:00）。**

## 第二小時 — 原理 II：雜訊、雷達方程式與課程地圖（1:00–1:50）

### 2.1 雜訊底線 — 接收機的對手（1:00–1:12）

訊號算完了；換敵人。每個溫度 T 的電阻都交出 kTB 的可用雜訊功率 — Johnson–Nyquist，
今天先陳述，細節等第 10 講要用時再推。在 IEEE 參考溫度 T₀ = 290 K：

> N = kT₀B = −174 dBm/Hz + 10·log₁₀(B)

真實接收機比物理底線再糟 NF（雜訊指數，noise figure）— 它偷走的 SNR，以 dB 計
（第 10 講花一小時講它從哪來、串接時各級怎麼分攤責任）。所以工作底線是 kT₀B·F：

> SNR[dB] = P_r[dBm] − (−174 + 10log₁₀B + NF)

現在就點名兩顆旋鈕，因為作業會轉它們：**頻寬是稅** — B 每 ×10，底線抬高 10 dB；
NF 則是進門先繳一次。課程雷達帶 B = 1 MHz（底線 −113.98 dBm）、NF = 3 dB。

先擋掉必問題：「把 B 縮到零，不就什麼都聽得見？」因為訊號有結構 — 頻寬承載資訊
（通訊），也承載解析度（雷達，第 15 講：距離解析度 = c/2B）。B 是伺候兩個主人的
設計變數；作業 Q4 要你為一個選擇辯護。

### 2.2 雷達方程式 — 現場組裝（1:12–1:30）

板書，今天的主菜。單站（monostatic，一面碟形天線兼收發）雷達照射距離 R、雷達
截面積（radar cross section）σ 的目標。P_r 分五個物理步驟從左到右搭起來：

1. 目標處的功率密度：P_tG/4πR²（Friis 的前半）。
2. 目標攔截並再輻射：σ 的**定義**就是「若全向再輻射、恰能解釋回波的等效孔徑」。
   單位：m²。再輻射功率：P_tGσ/4πR²。
3. 回波再擴散一次：再除以 4πR²。**就是這一步 — 講慢一點 — R² 變成了 R⁴。**
4. 天線用孔徑 Gλ²/4π 接住（同一面碟、同一個 G — 單站）。
5. 真實雷達會漏：除以系統損耗 L。

> P_r = P_t G² λ² σ / ((4π)³ R⁴ L)  SNR = P_r / (kT₀B·F)

以及反向問題 — 操作員真正問的那個 — 在最低可用 SNR 處解出 R：

> R_max = [ P_t G² λ² σ / ((4π)³ kT₀B·F·L·SNR_min) ]^(1/4)

**最外面那個 ¼ 次方統治一切。** 距離加倍要付 12.04 dB（第 3 小時會拿單向的 6.02
對照著量）。發射功率加倍只買到 19% 的距離（2^¼ = 1.189）。σ 砍 4000 倍 — 客機
到無人機 — 偵測距離只縮 7.95 倍。四次方根讓雷達的每一分改良都貴得殘忍，也讓
匿蹤只是**划算**，而非魔法。

RCS，老實講，九十秒：σ 不是目標的面積 — 是目標**如何散射**，而且隨視角
（aspect angle）與頻率劇烈擺動（戰鬥機機鼻方向 1 m²，側面可以 100 m²）。全班
共用的帳面數字：客機 ≈ 40 m²（+16 dBsm）、戰鬥機 ≈ 1 m²（0 dBsm）、小型四旋翼
≈ 0.01 m²（−20 dBsm），以及讓無人機問題變難的那個數字 — 大型鳥類也約 −20 dBsm。
分辨它們是第 15 講微都卜勒（micro-Doppler）的故事；今天只問**看不看得見**。
起伏、Swerling 模型、「≈」藏了什麼：第 14 講。

### 2.3 課程雷達會客（1:30–1:40）

介紹全課程要一路升級的儀器 — **課程雷達**，一部緊湊型 X 頻段周界監視雷達：
f = 10 GHz、P_t = 10 kW、G = 33 dBi、B = 1 MHz、NF = 3 dB、L = 6 dB、偵測門檻
SNR_min = 13 dB（今天先當佔位數字；第 14 講用誠實的 P_d/P_fa 數學換掉它）。

三位客人上黑板，用 dB、出聲算 — 這正是作業的計算，第 3 小時會印出來：

- **客機，σ = 40 m²：R_max = 32.65 km。**
- **戰鬥機，σ = 1 m²：R_max = 12.98 km**（σ 掉 16 dB；距離掉 16/4 = 4 dB = ×0.40）。
- **無人機，σ = 0.01 m²：R_max = 4.11 km。**

然後是全班會記住的現實檢查：*這部雷達能不能像航路監視雷達一樣，在 400 公里外
看見客機？* (400/32.65)⁴ ≈ **需要 22,500 倍的功率-孔徑乘積。** 這就是為什麼
ARSR 級的雷達用百萬瓦發射機、揹著一棟房子大的天線，也是為什麼沒有人在 400 公里
外偵測無人機。R⁴ 的暴政，一個數字講完。

戰場故事，60 秒：某海岸監視案，對漁船規格 200 公里，驗收那週客戶問了水上摩托車。
同一部雷達，σ 掉約 23 dB，距離安靜地除以 3.8。沒有人說謊；四次方根只是不在乎
行銷文案。作業 Q2 就是這個故事，把無人機放進水上摩托車的座位。

### 2.4 課程地圖 — 這部雷達的每個方塊都是一講（1:40–1:48）

投影片提示：雷達方塊圖，每個方塊蓋上講次編號。

沿訊號路徑走：發射機把能量送進**傳輸線**（L2），經過**匹配網路**（L3、6），用
**散射參數**（S-parameters，L4）描述，跑在**微帶線與波導**（L5）上，穿過**耦合器**
（L7）與**濾波器**（L8–9）到**天線陣列**（L13）；回波經**低雜訊放大器與雜訊預算**
（L10–11）、**混頻**（L12）落地，最後由**雷達方程式**（L14）、**FMCW／都卜勒處理**
（L15）與**波束成形加避撞邏輯**（L16）收尾。今天你從外面幫整部機器標了價；十六週
後，每個箱子你都打開過。

把差異化說白：多數微波課停在放大器；多數雷達課假設微波零件用郵購寄到。這門課
拒絕這種分工 — 偵測這條線（無人機、飛機、避撞）是被動電路存在的理由，被動電路
是偵測數字做得到的理由。

### 2.5 本小時回顧（1:48–1:50）

雜訊底線是 −174 + 10logB + NF，沒得商量；雷達方程式是 Friis 走兩趟、中間夾一個
σ，四次方根幫每項改良標價；課程雷達看客機到 32.65 km、看無人機到 4.11 km — 而你
知道為什麼。第 3 小時把算出這些數字的機器做出來，然後用一個沒標單位的數字弄壞它。

**休息（1:50–2:00）。**

### 3.2 dB 熱身（2:05–2:12）

Cell 3.2：`db()` 與 `undb()` 各一行，然後五個數字：db(2) = 3.0103、db(10) = 10、

### 3.3 λ 表（2:12–2:17）

Cell 3.3：一條 3 公分走線、六個頻率。1 MHz 時 10⁻⁴ λ — 導線。2.4 GHz 時 0.24 λ —
過了 λ/10 線，是元件。10 GHz 時 1.0 λ — 是天線。77 GHz 時 7.7 λ — 是分布式系統。
指著 2.4 GHz 那列：*這就是為什麼你筆電的 WiFi 區看起來像水管工程，不像配線。*
第 2 講就從這張表的後果開始。

### 3.4 Friis 算兩遍 — 裁判原則的現場示範（2:17–2:25）

Cell 3.4：WiFi 鏈路算兩遍 — 一遍是黑板上的 dB 鏈，一遍是完全不碰 dB、直接走物理
（密度、孔徑、kTBF）的瓦特鏈。兩邊都印 P_r = −46.03 dBm、SNR = 47.93 dB（50 m），
一致到 0.0e+00 dB。把寓意說出口，因為它就是作業的設計：*兩個獨立實作、一個答案 —
一旦不合，就是有人把單位搞混了，而且會吵得很大聲。*這就是「函式庫是裁判、不是
球員」在裁判恰好是換了衣服的物理時的樣子。

### 3.5 雷達方程式開跑（2:25–2:33）

Cell 3.5：課程雷達會客 — 32.65、12.98、4.11 km 三行印出。接著量兩個指數：距離
10→20 km 加倍要 12.04 dB（單向的 6.02 印在旁邊對照），以及 400 公里之問：22,524×。
作業裡 σ×2 那行先讓大家猜再跑 — 剛看完 2^¼ = 1.189 的班，還是會對「功率加倍
只移這麼一點距離」感到意外。

### 3.6 首次接觸 scikit-rf — 外加一堂誠實課（2:33–2:40）

Cell 3.6：載入 `skrf.data.ring_slot` — 真實的 2 埠 S 參數資料，75–110 GHz。畫
|S11|、|S21| 的 dB 圖（第 4 講教你讀它們）和史密斯圖（Smith chart，第 3 講教你
這張圖）。今天的重點只有一個：*這就是整個產業活在其中的檔案格式與物件模型，
而它只要三行 Python。*

然後是誠實課：建 `skrf.media.Freespace`，跑 1 公里，印出 |S21| = 0 dB。**自由
空間無損。** 1.4 節公式裡的「路徑損耗」從來不是介質的損耗 — 是擴散加孔徑的記帳，
所以它住在天線的項裡。一個順著俗語「空間吃訊號」走的函式庫什麼都裁判不了；
skrf 剛剛裁判了一個**觀念**。（這也是提醒：工具模擬的是實然，不是俗語。）

### 3.7 蓄意 bug — 30 dB 的謊言（2:40–2:44）

Cell 3.7，第一小時預告的重演：`db(10e3)` = 40.0 — 千真萬確的數字，單位是 dBW —
被填進要 dBm 的格子（該填 70.0）。下游每一項都「反正都是分貝」，什麼都沒崩，
無人機的偵測距離印成 23.09 km 而不是 4.11 — ×5.62，因為 30 dB 攤在四次方根上是
10^(30/40)。指著兩個數字：*它們看起來都像雷達距離。這就是單位 bug 致命的原因 —
它們產生「合理的錯誤答案」。* 解法不是警覺，是命名：`p_t_dbm` 收到 `db(p_t_w)`
時，讀的人會皺眉。作業工具箱全面強制這件事。

### 作業簡報（2:44–2:48）

然後是模組與兩個指令：

- 模組 1 是你主場的 dB 機械（WiFi 鏈路）；模組 2 是核心 — 雷達方程式正算**加
  閉式反解**；模組 3 是三位客人的判決。
- **預測先行。** Q1（六對十二）與 Q2（匿蹤買到什麼）要在跑之前作答 — 對一個
  數字下注，本身就是作業。

  是 Q2 的材料。
- 預算 ≤ 3 小時。AI 使用是預設且歡迎 — ANSWERS.md 裡的預測與對帳，才是必須
  出自你手的部分。
